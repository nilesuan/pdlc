# 02.5-solve-exit.md — Phase 02.5 (Solve) exit checklist

**Authoritative source:** [`../../handbook/02.5-solve.md`](../../handbook/02.5-solve.md); [`../docs/TECH_SELECTION.md`](../docs/TECH_SELECTION.md); [`../docs/ADR.md`](../docs/ADR.md); [`../frameworks/EXPERIMENTATION.md`](../frameworks/EXPERIMENTATION.md).

This checklist is run at the end of `/solve`.

## Done-when

- [ ] **Constraints written first.** `solutions/<slug>/constraints.md` exists and is dated before any candidate list. Residency, licence, compliance, regulated-data handling, cost ceiling, platform commitment, team capability each stated or explicitly marked not-applicable.
- [ ] **Decision register complete.** Every decision the solution depends on is listed, classified load-bearing / reversible / routine, and owned by one named person.
- [ ] **Classification justified.** Each load-bearing classification names what reversing it costs; each routine classification names why nothing depends on it.
- [ ] **Constraint elimination applied before benchmarking.** Every eliminated candidate is attributed to the constraint that killed it.
- [ ] **Shortlists are real.** Two to four candidates per load-bearing decision, or a recorded reason why fewer.
- [ ] **Spikes pre-registered.** Every spike has a record written before its code, carrying decision, candidates, representative workload, one primary metric with exact definition, threshold, guardrails, disqualifiers, time-box, owner.
- [ ] **Thresholds predate results.** No threshold in any spike record was set or amended after a measurement was taken.
- [ ] **Representative workload used.** The spike input is the real corpus or workload, or synthetic with a stated reason why real input was not lawful or available.
- [ ] **Metric segmented where input classes differ.** No aggregate that hides a wholly-failing input class.
- [ ] **Evidence tier tagged on every claim.** Untagged claims are treated as Tier 0 and do not support a decision.
- [ ] **Load-bearing decisions carry Tier 3 evidence**, or a recorded exemption naming why a lower tier suffices.
- [ ] **Selection ADRs filed** under `docs/adr/`, sharing the design-ADR sequence, one decision each.
- [ ] **Alternatives carry numbers.** Every spiked candidate's measured value is recorded; every eliminated candidate's disqualifying constraint is recorded.
- [ ] **Reversal cost stated** on every load-bearing selection ADR, as a number or a band.
- [ ] **Spike harnesses promoted** into the repo's test tree and wired to run in CI as regression gates.
- [ ] **Solution plan consumable.** `solutions/<slug>/solution-plan.md` lets `/design` and `/split` proceed without re-opening a decided question.
- [ ] **Open decisions listed** with what each is blocked on. An unlisted open decision resurfaces as rework in `/build`.

## Auto-rejection

| Trigger | Severity |
|---|---|
| Spike threshold set or changed after results were seen | Blocker |
| Load-bearing decision on Tier 0 or Tier 1 evidence with no stated exemption | Blocker |
| Spike run with no representative workload recorded | Blocker |
| Candidate benchmarked despite failing a hard constraint | Major (result unusable) |
| Selection ADR with one candidate and no disqualification of alternatives | Major |
| Alternatives rejected without the measured value that rejected them | Major |
| Primary metric swapped mid-spike, or decision made on a secondary metric | Major |
| Missing Reversal cost section on a load-bearing selection ADR | Major |
| Decision register containing unclassified entries | Major |
| Constraints file dated after the candidate shortlist | Major (constraint-first ordering violated) |
| Routine decision escalated to a full bake-off | Minor (verification effort disproportionate to stakes) |
| Spike code discarded rather than promoted to a regression gate | Minor |
| Evidence claim with no tier tag | Minor |

## What good looks like

- Someone outside the team can read `solution-plan.md`, disagree with a choice, and know exactly which measurement to re-run to make their case.
- The cheapest eliminations happened first. Most candidates died on a constraint in an afternoon; only the genuinely close calls consumed a spike.
- At least one spike disqualified a candidate the team expected to win. If every spike confirmed the prior, the thresholds were probably set to confirm it.
- The regression gates are running in CI on the day the plan is handed to `/design`, not promised for later.
- The number of bake-offs is small. A register with twenty load-bearing decisions has misclassified most of them.
